# Sri Lanka ACO Itinerary Optimizer - Final 165 POI Version

This project uses your uploaded real datasets:

- `pois.csv`: 165 tourist places
- `route_distance_matrix.csv`: real distance matrix
- `route_duration_matrix.csv`: real duration matrix
- `past_trips_dataset.csv`: cleaned historical trips after name mapping
- `past_trip_name_mapping.csv`: mapping from raw historical names to POI names

## Features

- Uses all POIs from your dataset as the candidate pool.
- User can select start place.
- User can either use all POIs or enter must-visit POIs.
- User enters number of days and hours per day.
- Direct user preference weighting:
  - attraction priority
  - budget priority
  - travel time priority
  - popular route priority
- Weather filtering using OpenWeatherMap API.
- ACO route generation for the complete trip route.
- Pareto filtering.
- Personalized route ranking from best to worst.
- Multi-day itinerary generation by splitting the optimized full route according to the daily time limit.
- Clear Sri Lanka map using Folium.
- Real road route using OSRM when internet is available.

## Optimization Method

The system applies Ant Colony Optimization (ACO) to generate and rank the complete trip route under the total trip constraints:

`total trip time = number of days * hours per day`

After the best full route is selected, the system splits that route into day-wise itineraries using the daily time limit. Therefore, ACO is not applied only to Day 1; it optimizes the overall route first, then the final route is divided into Day 1, Day 2, Day 3, and so on.

## Fixes (2026-07-27)

1. **Day splitter** – inter-day travel time is no longer zeroed. Real driving time between the last place of day D and the first place of day D+1 is charged to the new day.
2. **Alternative routes** – ranking always returns at least 4–5 distinct routes when feasible (Pareto first, then fill from full ranked list). Multiple diversity sources:
   - specialised preference ACO runs (max-satisfaction, min-time, min-cost, max-popular, balanced)
   - diverse must-visit orderings (permutations / randomised greedy / adjacent swaps)
   - neighbourhood variants of top routes
3. **ACO best selection** – fixed crash/incorrect key when choosing the iteration best ant.
4. **UI blink** – graph is loaded once via `@st.cache_resource`; Folium map uses `returned_objects=[]` and a stable `key` so the page no longer flickers/reloads on interaction.
5. **Independent specialised ACO runs** – pheromone state is restored after each run so preference variants stay independent.
6. **Default candidate pool** – when must-visit is empty and “Use all POIs” is off, a sensible set of popular Sri Lanka POIs is used so routes are non-trivial.

## Output Features

The application produces:

1. **Optimised travel itinerary** with ordered POI sequence
2. **Ranked list** of candidate routes from best to worst (score based on distance, travel time, stay duration, weather safety, historical popularity and user preference weights)
3. **Alternative itinerary options** (typically 3–4) generated by specialised preference runs and diverse orderings
4. **Travel route explanation** – short human-readable text explaining why each route is suitable
5. **Day-by-day plan** with real inter-day travel times
6. **Interactive map** of the best route (Folium + OSRM when internet is available)

## How ranking works

- ACO runs multiple times with different preference emphases so that genuinely different orders appear.
- Routes are scored on: satisfaction, cost, total time, total distance, historical similarity, weather safety and stay-duration balance.
- Pareto front is preferred; remaining slots are filled from the full ranked list so alternatives are never empty when multiple feasible orders exist.
